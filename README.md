# Threat Detection Principles: сигнатуры, сетевые правила и поведенческий анализ

Данный проект про то,**как детектировать угрозы**, а не только их классифицировать. 
Разбирала три разных уровня детекта: статичный файл (сигнатуры YARA), сетевой трафик
(правила Suricata) и поведение пользователя (UBA на Python).

Всё тестировалось в изолированной среде (Kali Linux в VirtualBox) на заранее
подготовленных тестовых файлах/дампах, без реального вредоносного ПО.

## Зачем я это делала

Я хотела разобраться как детект пишется руками:

- чем отличается сигнатурный анализ файла (YARA) от сигнатурного анализа
  сетевого пакета (Suricata) — и почему для обоих нужен один и тот же
  навык: находить уникальный, невоспроизводимый в чистом трафике паттерн;
- как из "просто нашла подозрительное" сделать правило, которое не будет
  давать false positive на легитимных данных;
- что поведенческая аналитика (UBA) — это вообще отдельный класс детекта,
  который не завязан на сигнатуры вовсе, а смотрит на паттерны действий.

## Задание 1 — YARA-сигнатуры для трёх файлов

Для трёх тестовых бинарных файлов (`file1.bin`, `file2.bin`, `file3.bin`)
написала по одному YARA-правилу на файл так, чтобы каждое правило
детектировало **строго свой** файл и не пересекалось с остальными.

**Условия, которые заложила в каждое правило:**
- уникальная hex-строка, характерная только для этого файла;
- обычная (ASCII) строка-маркер;
- в одном из правил — дополнительно условие по точному размеру файла
  (`filesize`), чтобы отсечь любые совпадения по контенту, но с другим
  размером.

**Чему научилась:**
- как искать в файле байтовые последовательности, которые с высокой
  вероятностью не встретятся в других (легитимных) файлах — то есть
  реально исключать false positive, а не просто написать правило,
  которое сработает на моём примере;
- разницу между `$hex_string` и обычной ASCII/wide строкой в YARA и
  когда какую использовать;
- как комбинировать условия через `and`/`or` в секции `condition`, чтобы
  правило было именно "и то, и то", а не "любое из".

Правила — в [`file1_rule.yar`](./file1_rule.yar), [`file2_rule.yar`](./file2_rule.yar),
[`file3_rule.yar`](./file3_rule.yar).

## Задание 2 — Suricata-правила для вредоносного трафика

В сгенерированном дампе `malicious_traffic.pcap` нашла 4 подозрительных
пакета и написала под каждый отдельное правило Suricata.

**Как проверяла:** прогоняла правила на дампе локально —

```bash
suricata -r malicious_traffic.pcap -l . -S suricata.rules
```

и смотрела `fast.log` — по каждому правилу должен появиться отдельный алерт.

**Чему научилась:**
- писать сигнатуры Suricata (`alert`, `content`, `offset`/`depth`,
  `sid`, `rev`) так, чтобы правило цепляло конкретный пакет, а не
  весь класс трафика;
- читать дамп в Wireshark осознанно — искать не "что выглядит странно",
  а конкретные аномалии на уровне протокола (нетипичные заголовки,
  подозрительные payload'ы, странные порты/флаги);
- разницу между детектом на уровне файла (YARA, офлайн) и детектом
  на лету на сетевом трафике (Suricata, real-time) — и почему вторая
  сигнатура почти всегда жёстче ограничена по производительности.

Правила — в [`my.rules`](./my.rules), результат прогона — в `fast.log`.

## Задание 3 — UBA: поведенческий анализ по ритму набора текста

Скрипт на Python, который просит ввести одну и ту же строку дважды,
замеряет промежутки между нажатиями клавиш в обоих случаях (через
`pynput`) и сравнивает ритм набора (`statistics`). Если среднее
отклонение больше 0.1 секунды — считает, что вводил другой человек.

**Чему научилась:**
- что такое User Behavior Analytics (UBA) как класс детекта — не "что
  произошло", а "похоже ли то, что произошло, на обычное поведение
  этого пользователя";
- как ловить события клавиатуры в реальном времени в Python
  (`pynput.keyboard.Listener`), а не просто читать готовую строку
  через `input()`;
- на практике увидеть главную проблему поведенческого анализа: у
  живого человека ритм набора никогда не бывает идентичным между
  двумя попытками, поэтому порог отклонения — это всегда компромисс
  между false positive и false negative, а не "правильное" число.

Код — в [`UBA.py`](./UBA.py).

**Запуск:**
```bash
pip install pynput
python3 UBA.py
```

## Итог

Этот проект — про написание правила, которое само эту атаку поймает. Дальше
интересно было бы объединить 2 направления: взять техники ATT&CK из
другого проекта и написать под них конкретные Suricata/YARA-правила —
получится что-то вроде мини detection engineering пайплайна.
